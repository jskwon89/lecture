## 확인 결과

- 내용 9개 화면과 순서, 네 구역 노트, 출처 ID와 NEXT를 검사했다. 3장 연결과 5장 전환, 마지막 7장의 쟁점별 찬반 정리 역할을 유지했다.
- 화면·대본·표·조문·풀이가 JSON 및 MD에 있고, DOCX 렌더의 해당 내용 페이지에 모두 나타나는지 대조했다. PASS.
- DOCX `W7_4장_구체적구성안과낭독대본_v23.docx`: 20쪽, 52330 bytes. SHA256 `da58edc4d54a8588c76f98361e4c3d35437692ed98202eb1746d526caa0c53f7`.
- Pretendard 기반 DOCX를 render_docx.py로 렌더하여 20쪽 모두 시각 점검했다. 표·문단의 잘림, 겹침, 깨진 한글, 빈 끝 페이지 없음. 각 내용의 화면 문구와 대본이 한 페이지에 배치됨.
- 보고·추인·7일/14일 조건과 치료비 부담·상환청구의 세부 설명은 강사용 자료에 보존했다. 사례의 출처 귀속과 기간 정의, 지역 운영 예의 적용 범위를 유지했다.
- 현재 인계와 변경 이력을 갱신하고 이전 버전은 보존했다. 공통 규칙·양식·실제 PPTX는 미변경. 전체 연구 게이트 통과나 후속 단원 완료로 표시하지 않았다.
- MANIFEST를 로컬에서 검증한 뒤 커밋한다. 원격 변경 파일을 읽어 바이트와 SHA256을 대조한 결과는 실행 기록에 남긴다.
