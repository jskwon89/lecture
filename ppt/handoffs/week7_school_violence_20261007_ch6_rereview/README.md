# 7주차 6장 재검수 인수인계

2026-10-07 사용자 승인으로 공통 검수 절차를 강화하고 6장 전체 10쪽의 화면 문구와 대본을 재검토했다.

1. ../../AGENTS.md와 ../../SCREEN_FIRST_REVIEW.md를 읽는다.
2. CONTENT.json 또는 SCREEN_AND_SCRIPT.md의 수정 문구를 기준으로 쓴다. DOCX는 화면과 그 아래 낭독 대본으로 구성된 10쪽 문서다.
3. REVIEW.md에서 각 페이지의 질문·인용·수정 전 문제·수정 이유·연결을 읽는다. 과거 실제 PPT 검토기록의 7 PASS/3 HOLD는 최신 판정으로 사용하지 않는다. 사용자 지적으로 2쪽의 이전 PASS를 철회한 이유도 남겼다.
4. SOURCE_UPDATE.md와 SOURCE_RECORDS.md·SOURCE_CASES.md를 사실 근거로 확인한다. 과거 원자료 검증의 사실 확인을 재사용한 것이며 과거의 내용 PASS를 승계하지 않았다.
5. 사용자 최신 로컬 PPT에 반영한 뒤 실제 PPT 전 페이지의 배치와 노트를 다시 확인한다. 노트에는 script만 넣는다.

내용 검수: 수정 문구 10쪽 PASS, HOLD 0, 미검토 0. DOCX 렌더 10쪽 확인. 실제 PPTX 수정본은 이번에 만들지 않았다. 입력 전체 파일은 W7_ch6_p1-10.pptx이며, 후속 rev1 파일은 2쪽 화면만 확인했다.

주요 수정: 1쪽 범위/정도 관계, 2쪽 두 대안과 제외 사건·제안자, 3쪽 자유형 상한, 4쪽 판단 이유의 쉬운 문장, 5쪽 사과 내용과 의사, 6쪽 기재유보와 삭제, 7쪽 반영방법, 8쪽 소송/집행정지의 주체와 결과, 9쪽 구체적 손해·공익, 10쪽 중립적 질문.

재생성: python build_docx.py [출력.docx]
기록 검사: python ../../tools/check_content_review.py CONTENT.json REVIEW.json
새 DOCX를 만들면 파일 해시와 REVIEW.json의 artifacts도 갱신하고 다시 렌더한다.

전체 목차와 1~5장 사용자 편집본은 바꾸지 않는다. 7장은 각 쟁점에서 서로 다른 입장의 주장과 근거를 정리하는 역할을 유지한다.
