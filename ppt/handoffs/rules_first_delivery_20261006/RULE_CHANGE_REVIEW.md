## 문제와 변경

전체 장을 처음 만들 때는 추상적인 설명과 논제 기여가 약한 페이지를 내놓고, 사용자가 한 페이지씩 질문한 뒤에야 대상·활동·연결을 구체화하는 반복이 있었다. 기존 FIRST-PASS PRECISION·SCRIPT-HIDDEN TEST의 내용 기준은 이미 있었으나, 첫 제출 전 전수 적용과 실제 검수 근거를 남기는 절차를 강화할 필요가 있었다.

- 절차 원문: `ppt/PPT_WORKFLOW.md` §4-4.
- 기록 양식: `ppt/PROPOSITION_ALIGNMENT_AUDIT_TEMPLATE.md` §4-1·§7. 별도 중복 템플릿을 만들지 않고 기존 양식을 확장했다.
- 내용 보강: CONTENT §2-3·§2-4의 자료 채택·직접성, §4-11의 프로그램 대상·활동·측정, §7의 비교 수준과 병행 관계.
- 전달 형식: 사용자가 발표자 노트에 대본만 요청하면 대본만 넣고 나머지 자료는 페이지 ID로 연결해 별도 보존한다.
- GPT·Claude 등 공통 진입점인 AGENTS §4와 README·current/README·Canonical에서 연결했다. 승인·적용관계는 SOURCE_MAP §28, 변경 이력은 CHANGELOG에 기록했다.

## 이번 변경의 검증 범위

- 9개 기존 문서의 변경 diff를 확인했다. 새 절 번호와 연결 대상이 존재하며 콘텐츠·WORKFLOW·검수 양식의 절 번호가 중복되지 않는지 확인했다.
- 기존 화면 단독 이해·원자료 확인·간결한 대본 원칙과 함께 읽었다. 간접자료 일괄 삭제, 원문에 없는 세부 추정, 매 화면의 논제 문구 반복, 검수 메모의 낭독으로 이어지지 않도록 명시했다.
- 내용 검수 절차는 제작자가 실제 내용을 읽고 판단하는 필수 작업이다. 문서 변경을 의미 이해까지 자동 인증하는 CI 구현으로 설명하지 않는다.
- 기존 PPTX·원자료·디자인 값·생성 코드는 변경 범위에 포함하지 않았다. 이번 작업이 W7 5장 전체의 수정·검수 완료를 의미하지 않는다.
- 전달 파일 목록은 `FILE_CHANGES.md`, 정확한 UTF-8 바이트의 검증 목록은 `MANIFEST.sha256`에 둔다. 커밋 뒤 원격 파일을 재조회하여 이 목록과 대조한다.
