# layout_kit ↔ 현행 Canonical 호환성 메모

기준일: 2026-09-22

상태: **사용 가능 — 사용자 승인 세 항목은 Canonical v1.6에 반영 완료**

이 키트는 그래프·표·흐름·글 부품의 재사용과 자동 배치를 위한 구현 라이브러리다. 현재 작업은 `ppt/current/README.md`에서 시작하며, 현재 사용자 지시와 `ppt/PPT_RULES.md`, `PPT_CONTENT_RULES.md`, `PPT_WORKFLOW.md`를 따른다. 키트 전체가 Canonical보다 우선하는 것은 아니다.

## 사용자 승인으로 공통 기준에 반영한 부분

| 항목 | 현행 적용 | 이전 해석의 정정 |
|---|---|---|
| 행 결론·보충 글자 | 결론 14pt Bold / 보충 12.5pt | 최종본에서 12.5/11.5pt로 되돌리지 않는다. 결과·판결 행도 결론 14pt를 적용한다. |
| 행 본문 배치 | 결론·보충·한정 줄 묶음을 행의 세로 가운데에 배치하고 글은 왼쪽 정렬 | 묶음의 행 내 위치와 텍스트박스 내부 위쪽 정렬은 양립한다. 내부 정렬을 근거로 묶음을 행 위쪽에 붙이지 않는다. |
| 제목 오른쪽 칩 | 사용하지 않음 | 사건번호는 제목 뒤 보통 굵기 또는 상단 밴드·본문의 사건 소개 한 곳에 보존한다. 별도 오른쪽 칩과 이를 위한 제목 폭 축소를 복원하지 않는다. |

상세 규칙은 `PPT_RULES.md` §5-1·§6-1·§6-4·§7, 승인 출처와 대체 범위는 `RULE_SOURCE_MAP.md` §15를 따른다. 위 세 항목은 더 이상 Canonical 충돌로 분류하지 않는다.

## 그대로 사용할 수 있는 부분

- `Box`, `split_h`, `split_v`를 통한 영역 분할
- 글·표·그래프·흐름 부품과 예시 조합
- 영역 부족 로그
- 행 높이 계산·정렬 보조
- 묶음 막대의 폭 기반 연도축 축약
- 겹선 제거 보조. 서로 다른 기능의 구조선까지 사라지지 않았는지는 실제 렌더로 확인한다.

## 별도 확인이 필요한 부분

1. **나머지 색·글자 역할** — 승인된 행 결론·보충 외의 `design.py` 값까지 일괄 채택하지 않는다. 다른 역할의 수치·색이 현행 Canonical과 다르면 해당 역할의 Canonical 기준을 적용한다.
2. **자동 글자 축소** — `fit.py`는 마지막 수단으로 0.5pt 축소를 허용한다. 현행 원칙은 공간 부족 시 내용·배치·분할을 먼저 검토하는 것이다. 축소 로그와 역할별 허용 크기를 확인하며 승인된 행 글자 크기를 자동으로 줄이지 않는다.
3. **실제 배치** — 행 높이 계산 결과와 본문 묶음의 시각적 중심, 잉크 보정, 위·아래 여백을 렌더에서 확인한다. 모든 텍스트박스의 내부 정렬을 무조건 가운데로 바꾸지 않는다.
4. **인용정보 보존** — 제목 뒤나 밴드에 인용을 넣을 공간이 없으면 본문 사건 소개에 둔다. 노트·자료대장에서 출처를 추적할 수 있어야 하며, 화면 이해에 필요한 사건번호가 사라지지 않게 한다.
5. **이전 도구 기본값** — 도구에 과거 12.5/11.5pt나 오른쪽 칩 분기가 남아 있어도 현행 결과물 기준으로 삼지 않는다. 생성 시 승인된 값을 명시하고 칩을 생성하지 않는다.

## 실제 제작 시 순서

1. `ppt/current/README.md`와 현행 Canonical을 읽는다.
2. `layout_kit/COMPONENTS.md`에서 필요한 부품을 고른다.
3. 예시 덱에서 가장 가까운 조합을 고른다.
4. 승인된 세 항목과 나머지 Canonical 역할값을 적용해 초안을 생성한다.
5. 사건번호·비교 라벨·요건·구조선 등 필요한 정보와 시각적 기능의 보존 여부를 대조한다.
6. 기존 QA와 전 장 렌더·개별 페이지·접촉시트 검수를 수행한다.
7. 키트 코드를 수정한 경우에만 해당 코드 변경과 재생성 결과를 `CHANGELOG.md`에 별도로 기록한다.

이번 변경은 규칙 문서의 정합화이며, 키트 코드·기존 PPTX를 변경하거나 새 PPT를 렌더 완료했다는 뜻이 아니다.

## 부품 수 표기

- 현재 master의 사용자 호출 부품: **26종** = 글 11 + 표 3 + 그래프 7 + 흐름 5
- `frame`, `Box`, 화면 분할, closing 등 골격 도구까지 포함하여 기존 handoff에서는 ‘27종’으로 부른다.
- 후속 부품 추가 패키지는 실제 코드가 반영될 때 COMPONENTS와 함께 갱신한다.
