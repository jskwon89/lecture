# 화면부터 읽는 페이지별 검수

기준일: 2026-10-07. 사용자 승인에 따라 WORKFLOW §4-4를 실행하는 필수 절차다.

## 1. 검토 대상 고정

실제 파일명, SHA-256, 전체 페이지 ID를 먼저 기록한다. 구성안·기존 PASS·작성자의 의도는 정답으로 두지 않는다. 화면과 대본이 구성안과 일치하는지는 전사 검사일 뿐 내용 검수의 근거가 아니다. 이미지 한 장을 추가로 받은 경우 해당 화면의 변경을 대조하고, 전체 파일에 반영되었다고 추정하지 않는다.

## 2. 화면을 먼저 설명하고 대본을 읽는다

각 페이지를 다음 순서로 검토한다. 전체 장을 한꺼번에 요청받았더라도 생략할 수 없다.

1. 대본을 가리고 제목·밴드·본문·하단을 순서대로 읽는다. 누가 누구에게 무엇을 했거나 제안했는지, 어떤 조건과 이유인지, 결과 또는 남는 질문이 무엇인지 실제 화면의 문구를 인용해 설명한다. 자료유형상 적용되지 않는 항목에는 구체적인 사유를 적는다.
2. 처음 듣는 사람이 되물을 질문을 작성한다. 핵심 질문의 답이 대본·상세자료에만 있으면 화면을 수정한다. 출처에서 확인되지 않는 사실은 설명을 매끄럽게 하려고 만들어 넣지 않는다.
3. 범위·기준·대응·보완·이러한·그것 같은 표현의 실제 대상을 문맥에서 찾는다. 어떤 법의 적용범위인지, 누구의 어떤 대응인지 되짚어야 하면 풀어 쓴다. 단어 자체를 금지하거나 이미 명확한 표현을 억지로 늘리지는 않는다.
4. 표의 행·열 관계를 설명한다. 대안/병행, 대상/활동/결과, 범위/정도의 차이를 같은 종류인 것처럼 묶지 않는다. 항목의 이름이 있다는 이유로 내용이 설명되었다고 판단하지 않는다.
5. 대본을 소리 내어 읽는 순서로 검토한다. 새로운 용어의 설명, 조건과 결과의 연결, 주어·목적어, 반복과 갑작스러운 전환을 수정한다. 낭독 대본에는 제작·검수용 해명을 넣지 않는다.
6. 직전 페이지의 마지막 문장 → 현재 첫 문장 → 현재 마지막 문장 → 다음 첫 문장을 대조한다. 자료가 바뀌면 새로운 자료의 주체와 성격을 밝히되 연결을 위한 설명을 반복하지 않는다.
7. 수정한 화면과 대본으로 1~6을 다시 확인한다. 수정 전 파일의 PASS를 수정 후 파일로 자동 승계하지 않는다.

## 3. 판정과 재개

- PASS에는 최종 화면의 인용, 그 인용으로 답할 수 있는 질문, 낭독 설명의 인용, 연결 문장, 수정 전 문제와 수정 결과가 있어야 한다.
- ‘구성안 일치’, ‘대본에서 설명’, ‘이미 검증’, ‘전반적으로 자연스러움’, ‘자료가 정확함’만으로 PASS하지 않는다.
- 사용자의 후속 질문에서 기본 설명 누락이 드러나면 해당 페이지의 기존 PASS를 철회하고, 같은 종류의 문제를 제출 범위 전체에서 다시 찾는다. 이전 검수기록을 몰래 덮지 않고 재검수 사유와 대체본을 연결한다.
- 수정할 필요가 없는 페이지는 유지 이유를 실제 문구로 남긴다. 전 페이지를 검토했다는 표시를 위해 불필요한 재작성·분할·방어문장을 늘리지 않는다.
- 보고는 내용 검수, 원자료 사실 확인, 파일 대조, 렌더 검수를 구분한다. 수정 제안만 작성하고 실제 PPT 반영·렌더 완료라고 보고하지 않는다.

## 4. 기록의 자동 점검

`tools/check_content_review.py CONTENT.json REVIEW.json`으로 페이지 누락·중복, 파일 해시, 실제 화면·대본 인용, 남은 문제와 판정의 충돌을 확인한다. CONTENT의 각 페이지에는 id, title, band, context, headers, rows, below, script가 필요하다. REVIEW에는 content_sha256, pages와 선택적 artifacts가 있다. 페이지별 id, status, screen_quote, screen_answer, script_quote, script_reason, previous_connection, next_connection, initial_issue, resolution, final_check, open_issues를 기록한다.

이 도구의 성공은 기록의 구조와 대응이 맞다는 의미다. 사실 정확성·이해 가능성·연결의 질을 자동 인증하지 않으며, 실제 읽기를 대신하지 않는다. 도구가 없거나 실행되지 않으면 자동 검사를 했다고 보고하지 않는다.
