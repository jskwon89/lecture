# GPT Layout Experiment — CONTENT → STRUCTURE → SLIDE

갱신: 2026-09-23  
상태: GPT 전용 실험 overlay  
적용: GPT가 실제 PPTX를 제작·수정하거나, GPT본과 Claude 등 다른 제작자의 실제 PPTX를 비교·평가할 때

## 0. 위계

이 문서는 공통 Canonical을 대체하지 않는다.

1. 사용자의 현재 명시적 지시
2. `ppt/AGENTS.md`
3. `ppt/current/README.md`
4. `ppt/PPT_CONTENT_RULES.md`, `ppt/PPT_RULES.md`, `ppt/PPT_WORKFLOW.md`
5. 주차별 확정 구성안·DOCX·직전 승인본
6. **이 문서**

충돌하면 위 순서가 우선한다.

2026-09-22 사용자 승인 디자인 정합화는 처음 Canonical v1.6에 반영되었고, 현재 공통 `PPT_RULES.md` v1.7이 이를 계승한다. `RULE_SOURCE_MAP.md` §15와 §16을 함께 적용한다. GPT 실험도 이 현행 기준을 따른다. 승인된 행 글자 크기·본문 묶음 배치·칩 미사용을 과거 Canonical 값으로 되돌리지 않는다. 세부 수치를 이 overlay에서 별도로 재정의하지 않는다.

---

## 1. 승인된 콘텐츠 구조를 먼저 잠근다

PPT를 만들기 전에 다음을 잠근다.

- 승인된 장수
- 승인된 순서
- 각 장의 기억목표
- 각 장의 핵심내용
- 다음 장 연결

사용자 승인 없이 표지·목차·연결장·보충장을 추가하지 않는다. 공간이 부족하면 먼저 사용자의 승인된 단위 안에서 압축하거나, 필요하면 “분할 필요”로 보고한다.

### 금지

- 7장 구성안을 9장으로 바꾸기
- 제1장만 만들라고 했는데 전체 강의 표지·목차를 추가하기
- 자료가 많다는 이유로 새 쟁점을 넣기

## 2. 텍스트를 도형에 넣기 전에 정보관계를 판정한다

각 슬라이드 제작 전 아래 중 하나 이상으로 정보관계를 판정한다.

| 정보관계 | 화면 구조 후보 |
|---|---|
| 범위 안 / 범위 밖 | 좌우 대조, 포함/제외 목록 |
| 세 요건 또는 여러 조건의 결합 | 3열 기준, `① + ② + ③`, 누적 조합 |
| 법정 범주 비교 | 3열 비교, 행머리글 표 |
| 법조문 각 목 나열 | 조문형 목록, 3분할 |
| 두 위험·두 개념 구별 | 좌우 대조표, 2열 matrix |
| 절차·진입경로 | 흐름도, 분기 흐름도, 단계도 |
| 시간 순서 | timeline |
| 규모·추이·분포 | 막대그래프, 큰 숫자, 수치표 |
| 연구 설계와 결과 | 설계 대조표 + 결과 그래프 |
| 종합 판단 | 쟁점지도, 조건표, 판단기준표 |

정보관계가 보이지 않으면 슬라이드는 아직 만들 준비가 된 것이 아니다.

## 3. 정보관계 → 기존 골격 순서로 고른다

새 레이아웃을 즉흥적으로 만들기 전에 다음 순서로 가장 가까운 기존 골격을 찾는다.

1. `ppt/templates/skeleton_types.pptx`
2. `ppt/templates/layout_kit/COMPONENTS.md`
3. `ppt/templates/layout_kit/examples/layout_examples.pptx`
4. `ppt/references/completed/`의 W2·W3·W4 완성본
5. 같은 주차의 성숙 참조본 또는 사용자가 제공한 승인본

기존 골격이 맞는데 새로 만들지 않는다. 단, 선택한 골격이 Canonical과 충돌하면 Canonical 값으로 보정한다.

## 4. 같은 표 형식을 편해서 반복하지 않는다

`row_table`, 카드형 목록, 3열 구조 등은 내용관계가 실제로 같을 때만 반복한다.

- 요건 결합이면 결합 구조가 보여야 한다.
- 개념 구별이면 좌우 차이가 보여야 한다.
- 절차이면 화살표·분기·도착점이 보여야 한다.
- 법정 범주 비교이면 같은 기준으로 나란히 놓아야 한다.

화면을 예쁘게 정렬하는 것보다 **내용의 관계가 화면 구조 자체에서 보이는 것**을 우선한다.

---

## 5. 긍정형 화면 문장 우선

상단 밴드와 장 제목은 반박문·금지문보다 긍정형 기준문을 우선한다.

- 나쁜 방향: “A가 아니라 B이다”
- 좋은 방향: “이번 장은 B를 기준으로 A와 구분한다”

다만 학생이 실제로 오해하기 쉬운 경우에는 본문 또는 하단에서 짧게 한계를 표시한다.

---

## 6. 기본 외곽선과 의도한 정보 구획을 구별한다

GPT가 생성한 PPTX에서는 텍스트박스·레이블·본문 상자에 PowerPoint 기본 외곽선이 남아 검은 네모 상자로 보이는 문제가 발생할 수 있다. 따라서 다음을 하드 QA로 적용한다.

- 제목, 본문, 각주, 라벨, NEXT, 상단 밴드 문장 등 **텍스트 전달용 상자는 외곽선 없음**이 기본이다.
- 정보관계를 나타내는 의도적 구분선, 흐름 화살표, 표 경계, 강조바, 직각 구획 상자는 사용할 수 있다. 공통 Canonical의 승인 팔레트·화면 유형을 따른다.
- 텍스트 전달용 상자의 기본 no-line과, 비교·묶음·절차를 위해 선택한 배경 도형의 경계를 구별한다. 모든 상자를 일괄 제거하지 않는다.
- 도형 경계의 역할을 먼저 확인한다. 기존본에서 비교·묶음·강조를 돕던 경계는 보존을 기본으로 하며, 의미 전달에 필요 없다는 전후 대조 근거가 있을 때만 제거한다(§13).
- 렌더 후 접촉시트와 실제 PPT 편집 화면에서 불필요한 검은 테두리·상자선이 보이면 실패로 판정하고 다시 저장한다.
- 사용한 제작 도구에서 텍스트 전달용 상자의 no-line 처리를 명시한다. 의도한 구획 상자의 선은 별도로 지정하고 실제 렌더로 확인한다.

## 7. 화면 자체가 2초 안에 의미를 보여야 한다

렌더 후 각 장을 2초만 보고 다음 질문에 답한다.

- 이 장은 무엇을 구분하는가?
- 어떤 조건들이 함께 필요한가?
- 어떤 경로로 이동하는가?
- 어떤 수치가 커졌거나 달라졌는가?
- 어떤 판단을 다음 장으로 넘기는가?

2초 안에 답이 보이지 않으면 구조를 다시 고른다.

### 7-1. 화면 단독 이해의 의미 완결성 — SCRIPT-HIDDEN HARD GATE

위의 2초 검사는 **구조가 눈에 들어오는지**를 보는 검사이고, 문장 의미의 완결성을 대신하지 않는다. 공통 Canonical v1.7의 화면 단독 이해 하드게이트를 별도로 적용한다.

- 대본·노트를 가린 뒤 슬라이드 한 장만 보고 '누가/무엇이 → 누구에게/무엇에 → 어떤 조건에서 → 무엇을 했고 → 무엇이 달라졌는가'를 설명할 수 있어야 한다.
- 사례에서 '신고 뒤', '협의 후', '연계됨', '처리됨'처럼 **행위 주체가 모호한 축약을 발견하면 레이아웃 조정 전에 문구부터 다시 쓴다.**
- 화면 공간이 부족하다는 이유로 주체·행위·대상 관계를 삭제하지 않는다. 부차적 세부를 줄이거나 장을 분할한다.
- 원문이 특정하지 않은 주체·원인·판단 이유를 추정해 채우지 않는다.
- 이 게이트를 통과하지 못한 장은 렌더가 깔끔해도 PASS가 아니다.

## 8. 렌더 후 접촉시트에서 장간 리듬을 본다

기존본·다른 제작자 참조본이 있으면 §13의 객체 대조와 페이지별 나란히 보기를 먼저 수행한다. 접촉시트는 전 장의 세부 누락 검사를 대신하지 않는다.

개별 장만 보지 않는다. 전체 접촉시트에서 확인한다.

- 같은 화면 유형이 반복되어 단조롭지 않은가
- 정보관계가 다른데 같은 표를 반복하지 않았는가
- 빈 장과 과밀 장이 섞이지 않았는가
- 상단 밴드와 하단 결론의 역할이 겹치지 않는가
- 다음 장 cue가 실제 진행과 맞는가
- 텍스트박스 외곽선이 검은 상자로 남지 않았는가

필요하면 장별 구조를 유지한 채 부품만 바꾼다.

## 10. W5 제1장 캘리브레이션

W5 제1장 Claude 참조본에서 학습할 점은 다음이다.

- 승인된 7장 구조를 바꾸지 않는다.
- 각 장이 같은 남색 골격을 공유하지만 정보관계에 따라 화면 형식이 바뀐다.
- p.3은 세 요건의 결합을 보여준다.
- p.5는 피해위험과 장래 범법우려를 같은 단어 “위험” 안에 섞지 않고 좌우로 분리한다.
- p.6은 송치와 통고를 같은 도착점으로 가는 서로 다른 진입경로로 보여준다.

참조본을 복제하라는 뜻이 아니다. **승인된 내용의 관계가 화면 구조로 보이게 하는 방식**을 따라간다.

## 11. 핵심 강조와 상자·선·색 면은 정보관계로 선택한다

**강조와 상자·선·색 면의 사용 여부는 내용의 중요도와 정보관계에 따라 선택한다. 일괄적으로 추가하거나 제거하지 않는다. 실제 렌더 화면에서 핵심의 식별, 묶음과 비교의 명확성, 읽는 순서, 여백의 균형을 확인하고 최종 결정한다.**

### 11-1. 강조 대상부터 정한다

- 각 장에서 가장 먼저 읽혀야 할 핵심과 뒤따르는 설명을 정한다.
- 크기·굵기·색·위치·여백을 함께 사용해 위계를 만든다. Canonical의 역할별 글자크기·팔레트·고정 좌표는 유지한다.
- 요건의 결합이나 동등한 비교처럼 핵심이 여러 요소의 관계라면, 관계를 이루는 요소를 같은 위계로 강조한다. 강조 요소를 무조건 하나만 남기지 않는다.
- 제목·요약·본문·하단을 모두 같은 강도로 강조해 서로 경쟁하게 하지 않는다. 핵심이 흐려질 정도로 강조를 일괄 약화하지도 않는다.

### 11-2. 상자·선·색 면의 선택

| 요소 | 사용할 이유 | 줄이거나 생략할 조건 |
|---|---|---|
| 직각 구획 상자 | 같은 묶음, 비교 대상의 경계, 절차의 출발·도착점을 명확하게 함 | 여백·정렬로 관계가 충분하거나 상자가 내용을 압도함 |
| 색 면·제목바 | 비교 열의 제목, 핵심 범주, 도식의 도착점을 빠르게 식별하게 함 | 모든 구역에 반복되어 중요도 차이가 사라짐 |
| 구분선 | 행·단계·구간의 경계를 보조함 | 다른 수단이 이미 같은 경계를 충분히 보여줌 |
| 굵기·글자색 | 핵심어·조건·대비 부분을 문장 안에서 식별하게 함 | 문장 전체에 중복 적용되어 강조 부분이 구별되지 않음 |

- 둥근 모서리·그림자·입체감이 있는 반복형 카드는 계속 사용하지 않는다. Canonical에서 허용한 직각 표·비교·도식 구획은 선택할 수 있다.
- 텍스트박스의 우연한 기본 테두리는 제거한다. 의도한 구획 도형은 그 역할을 설명할 수 있어야 한다.
- 같은 구역에 진한 세로선이나 제목바가 있으면 **동일한 경계를 중복 표시하는** 진한 가로선만 생략 대상으로 검토한다. 열 묶음의 시작선·요건별 상단선·결론의 경계선처럼 다른 기능을 맡은 선까지 제거하거나 일괄 약화하지 않는다. 실제 전후 화면에서 해당 기능이 유지되는지 확인한다.
- 보조선은 회색·옅은 선을 기본으로 한다. 진한 색의 사용 횟수보다 각 요소의 역할과 실제 화면에서의 시선 경쟁을 판단한다.
- 색 면·테두리·굵은 글씨·강조선을 한 대상에 기계적으로 모두 겹치지 않는다.
- 내용이 달라지면 상자의 크기와 여백을 재검토한다. 상자를 채우기 위해 문장을 늘리거나 글자를 줄이지 않는다.

### 11-3. 실제 렌더에서 최종 결정한다

1. 개별 장의 실제 렌더를 확인한다. 기존본·다른 제작자 참조본이 있으면 §13에 따라 두 실제 PPTX의 대응 페이지와 객체를 먼저 대조한다. 좌표와 객체 경계 검사만으로 완료하지 않는다.
2. 짧게 보았을 때 핵심과 읽는 순서, 비교·결합·절차 관계가 식별되는지 확인한다.
3. 글자와 상자의 관계를 확인한다. 내용이 떠 보이거나 한쪽에 치우치지 않는지, 선·배경이 글자보다 먼저 눈에 들어오는지 확인한다.
4. 의미 단위의 줄바꿈, 끝줄 고아, 대비, 정렬, 과밀·공백을 점검한다. 공통 Canonical의 실측 QA를 대체하지 않는다.
5. 상자의 효용이 불분명한 구역은 해당 부분에 한해 상자 있음/없음 또는 강조 강도 두 안을 비교하고 더 명확한 쪽을 고른다. 모든 장에 기계적으로 두 안을 만들지는 않는다.
6. 전체 접촉시트에서 장간 일관성과 리듬을 확인한다. 정보관계가 다른 장을 같은 모양으로 통일하지 않는다.
7. 비교 후 채택 이유는 내부 작업기록에 짧게 남긴다. 학생용 화면에 제작·검수 메모를 넣지 않는다.
8. 실제 사용하지 않은 PowerPoint 편집 화면 검수를 수행했다고 보고하지 않는다. 렌더 환경과 확인 범위를 구별한다.

W5 적용 예: p.3의 세 요건은 동등한 결합 강조, p.5의 두 비교 제목은 동일한 강도의 제목바, p.6은 가벼운 출발점 구획과 분명한 공통 도착점으로 검토한다. 특정 배치를 모든 장에 강제하는 규칙은 아니다.

## 12. 슬라이드 하단 각주는 기본적으로 넣지 않는다

GPT 실험본에서는 슬라이드 하단의 출처·근거 각주를 기본적으로 생략한다.

- 화면 하단 각주는 사용자가 명시적으로 요청한 경우에만 넣는다.
- 출처와 검증정보는 대본·자료집·주차별 source map·연구대장 등 별도 문서에서 관리한다.
- 법령 조문 자체가 본문의 핵심 내용이면 조문번호는 본문 안에 남길 수 있다.
- 출처 제거 때문에 사실검증을 생략해서는 안 된다. 화면에서만 숨기고 내부 검증은 그대로 수행한다.

공통 Canonical에서 특정 장에 출처표기가 반드시 필요하다고 명시한 경우에는 그 규칙이 우선한다.

## 13. 두 실제 PPTX를 직접 비교한 뒤 평가한다 — 필수 게이트

사용자가 GPT본과 Claude본(또는 다른 제작자의 참조본)을 제공한 경우, **두 실제 PPTX가 비교의 일차 근거**다. GPT본만 보거나, 대화 기억·과거 평가문·생성 코드·접촉시트만 보고 두 파일을 비교했다고 말하지 않는다. 이 절차는 재제작뿐 아니라 “비교해 달라”, “차이가 왜 생겼나”라는 평가 요청에도 적용한다.

### 13-1. 비교할 파일과 페이지를 고정한다

- 이미 제공된 GPT PPTX와 Claude PPTX를 작업공간·첨부에서 먼저 찾아 직접 연다. 파일을 확인하지 않은 채 사용자에게 차이를 다시 설명하거나 캡처를 더 제공하도록 요구하지 않는다.
- 파일명·SHA-256·실제 페이지 수·역할(현재 작업본/참조본)을 내부 기록에 남긴다. 비교하는 GPT 버전을 명시하고 과거 버전의 렌더를 최신본으로 취급하지 않는다.
- 실제 슬라이드 순서로 페이지를 대응시킨다. 장수·순서가 다르면 제목·내용으로 대응표를 만들고 추가·삭제·이동을 따로 표시한다.
- 각 PDF·이미지·접촉시트가 어느 PPTX 해시에서 생성됐는지 기록한다. 사용자 캡처와 렌더가 다르면 원본 객체·폰트·렌더 환경·출력 파일을 대조해 불일치를 좁힌다. 확인 전에는 원인을 버전 차이 또는 사용자 환경으로 단정하지 않는다.
- 파일 접근이나 렌더가 실패하면 확인 가능한 범위까지만 평가하고 미확인 항목을 명시한다. 전체 비교 완료 또는 PASS로 보고하지 않는다.

### 13-2. 객체 검사와 실제 화면 검사를 둘 다 한다

1. 두 PPTX의 전체 객체를 조사한다. 그룹 내부·표 셀·슬라이드 레이아웃/마스터 상속을 포함해 텍스트, 열/행 제목, 변수명·범주명, 선, 제목바, 색 면, 상자, 화살표, 하단 결론을 대조한다.
2. 텍스트·위치·역할로 대응 요소를 찾는다. 객체 ID·객체 개수가 같다는 이유만으로 보존됐다고 판정하지 않는다.
3. 대응 요소의 글자크기·굵기·색, 선 두께·색, 채움·투명도, 좌표·크기·겹침 순서의 변화를 확인한다. **객체가 삭제된 상태**와 **객체는 있으나 흰 글자·채움 제거·가림·낮은 대비 등으로 보이지 않는 상태**를 구별한다.
4. 두 덱을 같은 폰트·렌더 환경·해상도로 전 장 렌더하고, 대응 페이지를 같은 크기로 나란히 놓아 한 장씩 확인한다. 텍스트 추출 결과만으로 가시성을 판정하지 않는다.
5. 페이지 안에서 제목·상단 밴드 → 본문 열/행/도식 → 하단 결론 순으로 구역별 대조한다. 선명한 강조, 비교 대상의 식별, 묶음, 읽는 순서, 줄바꿈·정렬·여백을 각각 확인한다.
6. 그 뒤 전체 접촉시트에서 일관성과 장간 리듬을 본다. 최종 전달 PPTX를 고쳤다면 영향을 받은 페이지를 다시 대조하고, 전체 렌더와 접촉시트를 갱신한다.

### 13-3. 잘 작동하던 요소의 누락·약화를 먼저 판정한다

- 기존의 좋은 요소는 보존을 기본값으로 한다. 바꿀 때는 어떤 기능이 개선되는지 전후 화면으로 설명한다. 참조본의 오류·현행 지시와 충돌하는 요소까지 복원하지는 않는다.
- “깔끔하다”, “남색이 적다”, “선이 줄었다”만으로 개선이라 판정하지 않는다. 기존보다 핵심·비교·결합·경계가 덜 보이면 **시각적 기능 저하**로 기록한다.
- 열 제목·변수명·범주명·요건명·범례 등 내용을 식별하는 라벨은 장식이 아니다. 삭제되거나 렌더에서 보이지 않으면 **필수 정보 누락**이며, 큰 제목에 유사한 말이 있다는 이유로 통과시키지 않는다.
- 핵심 구조선과 보조선을 역할로 구분한다. 비교 열 위의 선, 동등한 요건 위의 선, 법조문 구간 경계, 하단 결론의 선·굵기, 밴드 왼쪽 강조표시는 각각의 기능을 평가한다. 색상이나 도형 종류만으로 일괄 약화하지 않는다.
- 본문을 모두 굵게 한 뒤 핵심어의 색만 바꾼 경우에도 실제 렌더에서 강조 차이가 보이는지 확인한다.
- 의도한 변경도 화면 기능이 나빠졌으면 수정 대상으로 남긴다. 실제 편집 기록을 확인하지 않은 채 누락을 “의도적으로 제거했다”고 사후 설명하지 않는다.

W5 제1장 필수 대조 항목: p.1 ‘논제 안’ 위 구조선, p.3 세 요건 위 선과 하단 결론의 강조·경계, p.4 법정 우범사유 구간의 위·아래 경계, p.5 ‘성착취 피해 위험 / 소년법상 장래 범법 우려’ 두 비교 열 제목의 존재와 실제 가시성, p.6 송치·통고 상단 밴드 왼쪽 강조표시의 대비. 이는 사용자 지적에서 얻은 검사 항목이며, 특정 최신 파일에서 모두 누락됐다는 사전 판정이나 모든 선을 무조건 진하게 복원하라는 지시는 아니다. 나머지 페이지도 같은 기준으로 전수 대조한다.

### 13-4. 평가 근거와 완료 판정

내부 비교 기록에는 다음을 남긴다.

| 대응 p.·구역/요소 | Claude/참조본 실제 상태 | GPT본 실제 상태 | 차이·기능상 영향 | 판정·조치 |
|---|---|---|---|---|
|  |  |  |  | 유지 / 개선 / 필수 정보 누락 / 시각적 기능 저하 / 의도한 차이 / 미확인 |

- 내용 수정에 따른 차이와 디자인 품질 차이를 구별한다. 최신 버전 또는 GPT 제작본이라는 이유로 더 낫다고 평가하지 않는다.
- 보고는 구체적인 페이지·요소·차이에 근거한다. 기존본에서 잘되던 점, GPT에서 개선된 점, 빠지거나 약해진 점을 함께 제시한다.
- 수정 작업에서는 필수 정보 누락·시각적 기능 저하를 해소하고 다시 대조하기 전까지 PASS/완료로 판정하지 않는다. 평가만 요청받은 경우에는 문제와 수정 권고를 기록하고, PPT 수정 완료로 표현하지 않는다.
- 검토한 PPTX와 사용자에게 전달한 PPTX가 같은 파일인지 해시로 확인한다. 검토한 화면에만 있고 전달본에는 없는 요소를 “보존했다”고 보고하지 않는다.
